# 스마트 분실물 키오스크

학교 분실물 보관·수령을 위한 터치스크린 키오스크 웹앱. 10.5인치 / 1920×1200(16:10) 태블릿 기준으로 만들어졌고, 완전 오프라인(로컬 네트워크만) 환경에서 동작합니다.

- **습득물 등록**: 4단계 위저드, 분류를 스무고개처럼 세분화, 본인확인용 키워드 태그 수집, 사진 필수
- **분실물 찾기**: 넓은 질문(층)부터 좁혀가는 후보 압축 → 키워드 기반 본인확인 퀴즈(5~8문항) → 사진 최종 확인
- **관리자 화면**: PIN으로 진입, 전체 항목 조회·수정·삭제, 사진 열람, 데이터 백업/복원, 전체 초기화
- **Node.js 서버 불필요**: 데이터는 브라우저 내장 저장소(IndexedDB)에 태블릿 안에서 직접 영구 저장됩니다. `index.html`/`style.css`/`script.js`를 정적 파일로 열어주는 앱(FreeKiosk, Localhost Lite 등)이면 무엇이든 동작합니다.

---

## 1. 구조

```
index.html   화면 마크업 (홈 / 등록 4단계 / 찾기 / 관리자 / PIN / 결과 화면들)
style.css    디자인 시스템 (관공서·도서관 키오스크풍 — 흰 배경, 남색 포인트, 홈 화면만 다크모드)
script.js    클라이언트 로직 전체 (등록/찾기/퀴즈/관리자/IndexedDB 저장)
server.js    (선택) Node.js가 있는 PC에서 개발/테스트할 때만 쓰는 정적 파일 서버. 태블릿 배포에는 필요 없음
data.json    초기 시드 데이터 참고용 파일. 실제 운영 데이터는 여기가 아니라 태블릿의 IndexedDB에 저장됨
```

## 2. 데이터는 어디에 저장되나 (중요)
>1.3.0 버전

https://jd-kiosk.cordbox.workers.dev/
이제 여기에 백업할 예정

클라우드플레어 서버를 사용하며 대략 230개 분실물을 저장할 수 있습니다.

단, 이 서버에는 이미 되찾아간 분실물 이미지만 지웁니다.

그 이미지는 로컬(내장 데이터베이스인 **IndexedDB**)에만 저장됩니다.


>1.2.3 버전

이 앱은 **서버가 전혀 없어도** 동작하도록 만들어졌습니다. 등록·수령·삭제 등 모든 데이터는 `script.js`가 브라우저 내장 데이터베이스인 **IndexedDB**에 직접 저장합니다 — Node.js도, PHP도, 별도 백엔드도 필요 없습니다.
- **Localhost Lite, FreeKiosk의 정적 파일 서빙 기능만으로 충분합니다.** 폴더를 지정해서 `http://localhost:8080` 등으로 띄우기만 하면, 그 안에서 IndexedDB가 알아서 데이터를 영구 저장합니다.
- 데이터는 **그 태블릿의 그 브라우저(그 앱)에 귀속**됩니다. 앱을 껐다 켜거나 태블릿을 재부팅해도 남아있지만, **브라우저/앱의 캐시·데이터를 완전히 초기화하면 함께 사라집니다.**
- 그래서 관리자 화면에 **데이터 내보내기/가져오기(백업)** 기능을 넣었습니다. 주기적으로(예: 학기 중 매주) "데이터 내보내기"로 JSON 파일을 다운로드해 안전한 곳에 보관해 두는 것을 권장합니다. 문제가 생기면 "데이터 가져오기"로 그 파일을 다시 불러와 복원할 수 있습니다.

### 태블릿 배포 (Localhost Lite 기준)

1. `index.html`, `style.css`, `script.js`, `data.json` 파일을 태블릿에 복사 (한 폴더에)
2. Localhost Lite에서 그 폴더를 Root Folder로 지정하고 **Start**
3. FreeKiosk로 `http://localhost:8080`(또는 Localhost Lite가 띄운 주소)을 열고 키오스크 잠금

`server.js`는 필요 없습니다 — 넣지 않아도 되고, 있어도 그냥 무시됩니다.

### PC/Node.js 환경에서 미리 테스트하고 싶을 때 (선택사항)

```bash
node server.js
```
정적 파일만 서빙하는 간단한 로컬 서버입니다(기능은 Localhost Lite와 동일). `http://localhost:8080`으로 접속해 동일하게 테스트할 수 있습니다. IndexedDB 기반 저장이라 이 경우에도 서버가 파일을 읽고 쓰지는 않습니다.

## 3. 습득물 등록 (4단계)

| 단계 | 내용 |
|---|---|
| 1 | 물품명(필수), 습득 날짜 — `[오늘]` / `[날짜 선택]` 버튼, 날짜 선택 시에만 캘린더 노출 |
| 2 | 습득 층(필수) → 층을 고르면 위치 목록이 자동으로 스크롤되며 나타남 |
| 3 | **분류를 스무고개처럼 세분화**: 분류(10종) → 세부 종류(예: 전자기기 → 핸드폰/보조배터리/태블릿/이어폰·헤드폰/스마트워치/노트북/계산기/충전기·케이블) → 일부는 더 자세히까지(예: 이어폰·헤드폰 → 유선/무선/헤드폰, 도서·노트 → 개인노트 → 스프링노트/무선노트/바인더노트) → 색상(그리드형, 실제 색상 배경 + 흰 글자·검정 테두리) |
| 4 | **사진(필수, 등록 완료 자체를 막음)**, 모델명/제작사(선택), 그리고 접이식으로 숨겨진 **내용물·숨겨진 특징·흠집**(본인확인 퀴즈 전용 키워드 태그), 재질/특징/사이즈, 메모 |

- 분류·세부종류·상세종류·색상·재질·특징·내용물·숨겨진 특징은 전부 **자가성장형 태그**입니다. 목록에 없으면 "+ 직접 입력"으로 새 키워드를 추가하고, 그 키워드는 이후 등록에서도 선택지로 남습니다.
- 등록 화면 어디서든 `◀`은 홈으로 바로 나가지 않고 `[이전]`과 동일하게 한 단계씩만 되돌아갑니다(1단계에서 누르면 그때 홈으로).
- 사진은 등록 시점에 **자동으로 최대 900px + JPEG 70%로 압축**되어 저장됩니다(원본 대비 대략 1/100 수준 용량).

## 4. 분실물 찾기

1. **후보 좁히기(넓은 질문부터)**: 층 → 위치 → 분류 → 세부종류 → 상세종류 → 색상 → 재질 → 특징 순으로 질문. 모든 질문에 "모르겠어요"와 "직접 입력"이 항상 있어 답을 몰라도 막히지 않습니다.
2. **최종 본인확인 퀴즈(5~8문항, 완전 결정론적 키워드 매칭 — 유사도 판단 없음)**
   - **태그형 필드(내용물/숨겨진 특징/특징/색상)**: `"이 물건에 [키워드]가 있었나요?"` → 그 키워드가 등록된 배열에 실제로 들어있는지(true/false)만 비교. 절반은 실제로 있는 키워드(정답 "네"), 절반은 다른 물건엔 있지만 이 물건엔 없는 키워드(정답 "아니요")로 랜덤 출제.
   - **단일값 필드(브랜드·모델/사이즈/재질/분류/세부종류/상세종류/층/위치)**: 등록값과 문자열이 정확히 일치하는지만 확인하는 객관식(오답 보기는 다른 실제 등록 데이터에서 가져옴).
   - 정답 기준: 전체의 75% 이상 또는 오답 1개 이하. "모르겠습니다"는 중립 처리.
3. **사진으로 최종 확인**: 퀴즈를 통과하면 보관 코드를 바로 공개하지 않고, 등록된 사진을 보여주며 "이 물건이 맞나요? [네]/[아니요]"로 한 번 더 확인합니다. 같은 조건으로 좁혀진 다른 후보가 있다면 "아니요"를 누를 때마다 다음 후보의 사진으로 넘어가고, 후보가 소진되면 "찾을 수 없음" 화면 후 홈으로 돌아갑니다.
4. **수령**: 성함만 입력하면 수령 처리되고, 행정실에서 보관 코드를 보여주면 수령하는 방식은 그대로입니다.

## 5. 관리자 화면

- 홈 화면 "N개 보관중입니다"의 **숫자를 더블클릭**하면 PIN 입력 화면으로 이동합니다.
- 기본 PIN은 `2010`이며, IndexedDB에 저장된 `settings.managerPin` 값을 관리자 화면에서 항목을 통해 직접 바꿀 방법은 아직 없고, 필요하면 초기 시드값인 `data.json`의 `settings.managerPin`을 바꾼 뒤 "전체 데이터 초기화"로 반영하면 됩니다.
- 전체 등록 물품(보관중/수령완료 모두) 목록과 **전체 대비 사진 데이터 예상 용량(MB)**을 함께 보여줍니다.
- 항목을 탭하면 사진 열람 + 모든 필드 수정 + 삭제 + 수령 상태 변경이 가능한 수정창이 열립니다.
- **수령 처리된 항목의 사진은 자동으로 지워지지 않고** 계속 관리자 화면에서 열람할 수 있습니다.
- **데이터 내보내기 / 가져오기**: 전체 데이터를 JSON 파일로 백업하거나, 백업 파일로 복원합니다. (2절 참고)
- "전체 데이터 초기화" 버튼은 처음 접속했을 때의 시드 데이터로 되돌립니다(발표/시연 준비용, 되돌릴 수 없음).

## 6. 홈 화면 다크모드

홈 화면만 다크 테마(#0f172a 배경)이고, 등록·찾기 등 다른 화면은 밝은 관공서풍 테마입니다. 홈에서 버튼을 눌러 다른 화면으로 넘어가면 `body.theme-dark` 클래스가 벗겨지며 배경이 부드럽게(0.6s) 전환됩니다. 배터리 절약 목적이며, 다시 홈으로 돌아오면 다크로 되돌아갑니다.

## 7. 태블릿 운영 관련 참고사항

- **화면 꺼짐/절전**: 안드로이드 기본 자동 화면 꺼짐(예: 15초) + FreeKiosk의 화면 보호기/화면 끄기 기능 조합으로 충분합니다. 일반 안드로이드 태블릿은 완전히 꺼진 상태에서 예약 시간에 저절로 켜지는 기능 자체를 지원하지 않으므로(RTC 웨이크업은 펌웨어 영역), 전원을 아예 끄기보다는 화면만 꺼두는 지금 방식이 맞습니다.
- **저장공간**: 사진은 등록 시 자동 압축되어 저장되지만, 그래도 시간이 지나며 쌓일 수 있습니다. 관리자 화면의 "사진 데이터 약 X MB" 표시로 주기적으로 확인하고, 필요하면 오래된 수령완료 건을 수동으로 삭제하세요.
- **캐시**: Localhost Lite/FreeKiosk가 파일에 캐시 방지 헤더를 안 붙일 수 있습니다. 파일을 새로 교체한 뒤에는 앱을 완전히 재시작하거나 브라우저 캐시를 한 번 지워서 최신 버전이 반영됐는지 확인하세요.

## 8. 커스터마이징 포인트

- **분류/세부종류/상세종류 트리**: `script.js`의 `seedData()` 함수 안 `meta.categorySubtypes`, `meta.subtypeDetails` (키 형식: `"분류|세부종류"`). 초기 배포 전에 여기를 고쳐서 파일을 교체하면 그 값이 처음 시드로 들어갑니다.
- **층/위치, 색상, 재질, 특징, 내용물, 숨겨진 특징 태그**: 마찬가지로 `script.js`의 `seedData()` 함수 안 각 배열
- **관리자 PIN**: `seedData()`의 `settings.managerPin` (기본 `2010`)
- **퀴즈 문항 수/필드 우선순위**: `script.js`의 `TAG_FIELDS`, `CHOICE_FIELDS`, `MIN_QUESTIONS`, `MAX_QUESTIONS`
- **사진 압축 강도**: `script.js`의 `compressImageFile(file, maxDim, quality)` 기본값(900px / 0.7)
- **디자인 토큰(색상/여백)**: `style.css` 상단 `:root` 변수, 홈 화면 다크 테마는 `body.theme-dark` 관련 규칙

> `seedData()`를 고친 뒤에는, 이미 IndexedDB에 데이터가 있는 태블릿이라면 관리자 화면의 "전체 데이터 초기화"를 눌러야 새 시드값이 반영됩니다 (기존 데이터가 있으면 시드는 최초 1회만 적용되기 때문입니다).
