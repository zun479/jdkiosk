# 스마트 분실물 키오스크 — 라이브 버전

학교 분실물 보관·수령을 위한 터치스크린 키오스크 웹앱. 10.5인치 / 1920×1200(16:10) 태블릿 기준으로 만들어졌습니다.

**"라이브 버전"** = 로컬 저장(IndexedDB)이 기본이고, 추가로 인터넷이 될 때 Cloudflare에 자동 클라우드 백업까지 하는 버전입니다. 인터넷이 전혀 없거나 클라우드 연동을 아예 원치 않으시면 **"로컬 버전"**(별도 제공)을 쓰세요.

---

## 1. 이 패키지에 포함된 파일

| 파일 | 용도 |
|---|---|
| `index.html` | 화면 마크업 |
| `style.css` | 디자인 |
| `script.js` | 클라이언트 로직 전체 (등록/찾기/퀴즈/관리자/저장/클라우드 백업) |
| `cloudflare-worker.js` | Cloudflare Worker 코드의 백업 사본 (참고용 — 태블릿엔 안 올라감, Cloudflare 대시보드에 이미 배포돼 있어야 함) |
| `README.md` | 이 문서 |

**태블릿에는 `index.html`, `style.css`, `script.js` 3개만 올리면 됩니다.**

### 이제 필요 없어진 파일 (더 이상 안 씁니다)
- **`data.json`** — 예전엔 서버가 읽던 실데이터 저장 파일이었지만, 지금은 `script.js` 안에 초기 시드 데이터(`seedData()` 함수)가 내장돼 있어서 필요 없습니다.
- **`server.js`** — 예전엔 Node.js로 돌리던 로컬 서버였지만, 지금은 `script.js`가 IndexedDB에 직접 저장하므로 Node 서버 자체가 필요 없습니다. Localhost Lite/SHTTPS+ 같은 순수 정적 파일 서빙 앱만 있으면 충분합니다.

두 파일 다 지우고 배포하셔도 전혀 문제없습니다.

## 2. 태블릿 배포 방법

1. `index.html`, `style.css`, `script.js` 세 파일을 태블릿의 한 폴더에 복사
2. SHTTPS+(또는 Localhost Lite)에서 그 폴더를 Root Folder로 지정하고 Start
   - **Allow file modification**, **Enable WebDAV**, **CGI/Commandline scripts**는 전부 꺼두세요 (우리 앱은 서버가 파일을 쓰거나 명령을 실행할 일이 없습니다)
   - **Autostart on boot**는 켜기, **Auto shutdown by inactivity**는 반드시 끄기
   - **Restrict network interfaces**를 켜서 localhost(127.0.0.1)로만 제한하는 것을 권장 (외부에서 접속 못 하게)
3. FreeKiosk에서 그 주소(`http://localhost:8080` 등)를 열고 화면 잠금
4. 화면 꺼짐은 안드로이드 기본 자동 절전 + FreeKiosk 화면 보호기 조합으로 충분 — 전원을 완전히 끄는 방식은 예약 재부팅을 지원하지 않으니 쓰지 마세요

## 3. 데이터는 어디에 저장되나

- **1차 저장소(항상 동작)**: 브라우저 내장 저장소인 **IndexedDB**. 등록·수령·삭제 전부 즉시 여기 저장되고, 태블릿을 껐다 켜도 남아있습니다. 인터넷이 전혀 없어도 완전히 정상 동작합니다.
- **2차 저장소(있으면 좋은 보너스)**: 데이터가 바뀔 때마다 인터넷이 되면 **Cloudflare Worker + KV**에도 자동으로 백업됩니다. 실패해도 등록/수령 같은 실제 기능엔 전혀 영향 없이 조용히 다음 기회에 재시도됩니다.

### 클라우드 백업 동작 방식
- **이벤트 기반**: 정해진 시각이 아니라 데이터가 바뀔 때 트리거됩니다.
- **최소 10분 스로틀**: 짧은 시간에 여러 건이 바뀌어도 실제 업로드는 10분에 한 번만 나갑니다 (Cloudflare KV 무료 티어 하루 쓰기 1,000회를 안전하게 지키기 위함).
- **실패 시 자동 백오프**: 계속 실패하면 재시도 간격이 최대 1시간까지 늘어납니다.
- **인터넷 복구 시 즉시 재시도**: 브라우저의 `online` 이벤트를 감지해서 와이파이가 다시 잡히면 스로틀 무시하고 바로 시도합니다.
- **수령완료 항목은 클라우드에서 사진 제외**: Cloudflare KV는 값 하나당 25MB 제한이 있어서, 이미 수령된(끝난) 물건은 클라우드 백업에서만 사진을 빼고 나머지 정보만 남깁니다. 로컬(관리자 화면)에는 사진이 그대로 다 남아있습니다.

## 4. 습득물 등록 (4단계)

| 단계 | 내용 |
|---|---|
| 1 | 물품명(필수), 습득 날짜 — `[오늘]` / `[날짜 선택]`, 날짜 선택 시에만 캘린더 노출 |
| 2 | 습득 층(필수) → 층을 고르면 위치 목록이 자동 스크롤로 나타남 |
| 3 | 분류(10종) → 세부 종류 → (일부는) 더 자세히까지 스무고개식 세분화 → 색상(실제 색상 배경 그리드) |
| 4 | **사진(필수, 없으면 등록 자체가 막힘)** + **직접 촬영 버튼**(전면 카메라, "다시 촬영" 가능), 모델명/제작사(선택), 접이식 내용물·숨겨진 특징(본인확인 퀴즈 전용), 재질/특징/사이즈, 메모 |

분류·세부종류·상세종류·색상·재질·특징·내용물·숨겨진 특징은 전부 **자가성장형 태그** — 목록에 없으면 "+ 직접 입력"으로 추가됩니다. `◀`는 홈으로 바로 안 나가고 `[이전]`과 동일하게 한 단계씩 되돌아갑니다.

## 5. 분실물 찾기

1. **후보 좁히기**: 층 → 위치 → 분류 → 세부종류 → 상세종류 → 색상 → 재질 → 특징. 모든 질문에 "모르겠어요"·"직접 입력" 있음.
2. **본인확인 퀴즈(5~8문항, 완전 결정론적 — 유사도 판단 없음)**
   - 태그형(내용물/숨겨진특징/특징/색상): `"[키워드]가 있었나요?"` → 실제 등록 배열에 있는지 true/false만 비교
   - 단일값(브랜드·모델/사이즈/재질/분류/세부종류/상세종류/층/위치): 문자열 완전 일치 객관식
   - 정답 기준 75% 이상 또는 오답 1개 이하
3. **후보가 여러 개면** 퀴즈 전에 사진으로 먼저 골라볼 수 있음 (위치/날짜를 몰라도 사진은 알아볼 수 있으므로). 틀리면 최대 2번 재시도.
4. **최종 사진 확인** → **학번(5자리 숫자)+실명(한글/영문 2자 이상, 특수문자·숫자·공백 불가) 입력해야만 수령 완료 버튼 활성화**

⚠️ 위치/날짜를 몰라도 사진만으로 수령까지 가능한 구조라, 관리자 화면에는 그 경로로 수령된 항목의 이름 옆에 **빨간 동그라미**가 표시됩니다 (하단에 10px 크기로 설명 문구도 같이 뜸).

## 6. 관리자 화면

- 홈 화면 "N개 보관중입니다"의 **숫자를 더블클릭** → PIN 입력(기본 `2010`, `script.js`의 `seedData()` 안 `settings.managerPin`에서 변경)
- 전체 항목 목록 + 사진 데이터 예상 용량 + 클라우드 동기화 상태 표시
- 항목 탭하면 사진 열람 + 전체 필드 수정 + 삭제 + 수령 상태 변경
- **데이터 내보내기/가져오기**(JSON 파일 수동 백업), **자동 백업 파일 지정**(지원 브라우저에서 파일 하나를 지정해두면 계속 덮어써서 저장), **클라우드에서 복원**(확인 후 최신 클라우드 백업으로 덮어씀)
- **데이터 유실 의심 경고**: 관리자 화면 진입 시 클라우드 기록과 로컬 개수를 비교해서, 로컬이 비정상적으로 0인데 클라우드엔 과거 기록이 있으면 빨간 배너로 경고
- "전체 데이터 초기화": 최초 시드 데이터로 되돌림 (되돌릴 수 없음)

## 7. 홈 화면

- 다크 테마 고정, 다른 화면으로 넘어가면 부드럽게(0.6s) 밝은 테마로 전환, 홈으로 돌아오면 다시 다크로
- 좌하단에 작은 **[키오스크 상태]** 박스: 인터넷 접속 여부(사용자가 화면 이동할 때만 갱신, 실시간 아님) / 클라우드 자동 재시도 상태 / 마지막 동기화 시각 / 마지막 복구 시각 / 배터리(지원 브라우저에서만, 폴링 아닌 이벤트 기반이라 배터리 소모 거의 없음)

## 8. 커스터마이징 포인트

모두 `script.js` 안에 있습니다 (더 이상 `data.json`을 안 씀):
- **분류/세부종류/상세종류, 층/위치, 색상, 재질, 특징, 내용물, 숨겨진 특징 태그**: `seedData()` 함수
- **관리자 PIN**: `seedData()`의 `settings.managerPin`
- **퀴즈 문항 수/필드 우선순위**: `TAG_FIELDS`, `CHOICE_FIELDS`, `MIN_QUESTIONS`, `MAX_QUESTIONS`
- **사진 압축 강도**: `compressImageFile(file, maxDim, quality)` 기본값(900px / 0.7)
- **클라우드 스로틀 간격**: `CLOUD_SYNC_MIN_INTERVAL_MS`, `CLOUD_SYNC_MAX_INTERVAL_MS`
- **Cloudflare 연동 정보**: `CLOUD_API`, `CLOUD_TOKEN`
- **디자인 토큰**: `style.css` 상단 `:root` 변수

`seedData()`를 고친 뒤에는, 이미 데이터가 쌓인 태블릿이라면 관리자 화면의 "전체 데이터 초기화"를 눌러야 새 시드값이 반영됩니다.

## 9. Cloudflare Worker (`cloudflare-worker.js`)

Cloudflare 대시보드(Workers & Pages → 해당 Worker → Edit code)에 이미 배포돼 있어야 합니다. 여기 포함된 사본은 참고/백업용입니다.

| Method | Path | 설명 |
|---|---|---|
| POST | `/backup` | 백업 저장, `maxItemCount`(역대 최대 보관 개수) 갱신 |
| GET | `/backup` | 최신 백업 전체 반환 (복원용) |
| GET | `/status` | 가벼운 상태만 반환 (유실 감지용) |

모든 요청은 `Authorization: Bearer <AUTH_TOKEN>` 필요. KV 바인딩 변수명은 `KIOSK_BACKUP`.
